- (decision) AD-1..AD-20 assigned as stable IDs. Paradigm named: reactive document-store core with durable-intent orchestration at the edges. Prevents: rationale drifting from the doc into code review.
- (decision) AD-5 changed the JWKS mechanism vs the source doc: prefer a base64 data: URI JWKS in Convex over a hosted Vercel /.well-known/privy-jwks.json route. Convex documents data-URI JWKS support and Privy publishes no JWKS endpoint, so the hosted route is an avoidable moving part. Vercel token-bridge remains the fallback.
- (decision) AD-20 added a build constraint the source doc lacked: do not add @stylexjs/babel-plugin to the Next.js App Router app - it disables SWC and breaks next/font. Sourced from Astryx docs.
- (constraint) Dependency direction is a rule, not a diagram: shell never calls a Convex action or an external service directly; adapters never hold domain logic; mutations never perform I/O.
- (constraint) Money field naming is enforced: every integer money field ends in Minor (fiat) or Atomic (crypto). A field without that suffix is not money.
- (assumption) Stack versions in the Stack table are 'current stable at 2026-08-21' rather than pinned. Day 0 must pin exact versions in package.json, especially React 19 and Astryx Beta.
- (open-question) OQ-1 / research R-1: Convex may normalize a bare issuer to https://<value> while Privy tokens carry iss='privy.io'. Exact-match behavior must be confirmed on Day 0 before AD-5's primary path is trusted.
- (open-question) Research R-4: DFlow order response documents no orderId and no expiry field. settlementIntents.dflowOrderId cannot be assumed; My Tab must own quote TTL and idempotency, deriving freshness from blockhash plus a My Tab-side deadline.
- (decision) AD-14 amended: Convex HTTP Actions are the single Telegram webhook/bootstrap trust boundary; Vercel performs no privileged Convex write. Telegram bot-admin membership verification and lifecycle are mandatory.
- (decision) AD-10 amended: DFlow is sync-only and transaction validation is owned by a versioned fail-closed program/instruction/writable-role manifest with explicit v0/ALT, signer, compute, priority, ATA, and sponsor caps.
- (decision) AD-11 amended and AD-21 added: submitted or unknown broadcasts remain non-retriable until finalized blockhash-expiry and signature-absence proof; finalized parsed confirmation alone moves the ledger.
- (decision) AD-17 amended: sponsor exposure uses atomic multi-dimensional reservations with binding production caps, UTC reset windows, release/settle behavior, environment isolation, and an immediate pre-sign kill-switch check.
- (decision) AD-7 and AD-12 amended: reopen appends immutable obligation supersession events, rejects unresolved broadcast states, and never mutates prior obligations.
- (decision) AD-22 added: production THB-to-USDC accounting uses immutable integer-rational Frankfurter Bank of Thailand snapshots with bounded freshness and fail-closed stale behavior.
- (decision) AD-23 added: receipt bytes are served only through an authenticated Convex HTTP Action and have fixed deletion periods; reusable Convex storage URLs are forbidden.
